Whole-personal/account deletion is distinct and excludes instructor-controlled records. Jobs snapshot/check **all relevant ancestor fences** and the authorization epoch at admission, immediately before egress and before result commit; dispatch is serialized against revocation.                                                                      |
| Rubric **F4** — parent completion                           | **Resolved** | [AD-5](../architecture-shared-technical.md#L79-L80) defines a versioned parent requirement manifest pinning required/optional child releases. [AD-8](../architecture-shared-technical.md#L101) requires every required child award, excludes optional children from blocking, and preserves earned version-scoped awards. Plan edits/explicit child switches create a new parent requirement version; roadmaps and reports consume the same progress truth, with separate review indicators and D1 browsing rules.                     |
| Rubric **F5** — review verdict/policy handoff               | **Resolved** | [AD-13](../architecture-shared-technical.md#L135-L137) makes Assessment/progress's shared evaluator authoritative for a review-purpose verdict. Start snapshots pin the studied release and its **latest effective review-policy revision**, falling back to the published policy; pass mark, rubric and items are disclosed/snapshotted. Later edits do not change that review. Assisted, under-review and provisional instructor results cannot advance intervals; confirmation resolves the same review idempotently. Review cannot write completion/recovery credit.                                            |
| Rubric **F6** — confirmed-plan generation admission         | **Resolved** | [AD-7](../architecture-shared-technical.md#L92-L93) requires an authorized immutable confirmed plan revision and source revisions for full generation. Edits require new confirmation; workers cannot substitute the latest plan for the queued revision. Stale/canceled references yield an explicit conflict/pending outcome with saved input. Skipping the diagnostic neither blocks confirmation nor grants an exemption.                                                                                                                                                                                       |
| Compatibility **F1** — deletion identity/fence disagreement | **Resolved** | [AD-4](../architecture-shared-technical.md#L72) now determines one common outcome for A-only, B-only and A+B work: deleting A denies A and A+B descendants, preserves B-only work, and prevents late A-dependent results. AD-9's compact job-envelope wording does not override the explicit all-ancestor admission/egress/commit rule. Seven-day active purge, bounded backups and restore suppression remain binding.                                                                                                                                                                                             |
| Compatibility **F2** — applicable review threshold          | **Resolved** | [AD-13](../architecture-shared-technical.md#L135) selects the latest effective review policy **for the learner's pinned release at review start**, not an independently chosen completion-linked threshold. Thus a 75% review passes if a 70% policy is now effective for that release, even if completion used 80%; a later edit cannot change the started review. Existing recovery chains retain their root policy under [AD-8](../architecture-shared-technical.md#L100), so the review clarification does not mix recovery thresholds.                                                                         |
| Security **SEC-01** — restored stale authority              | **Resolved** | [AD-17](../architecture-shared-technical.md#L162-L164) closes the non-deletion restore path, not merely old-cookie reuse. The journal is content-free, independently retained, bounded to the maximum backup/restore horizon and checked for completeness under [AD-4](../architecture-shared-technical.md#L73). Restored queue work cannot resume before protective state is reconciled. No indefinite audit/event-sourcing requirement is introduced.                                                                                                                                                             |
| Security **SEC-02** — root-specific deletion                | **Resolved** | [AD-4](../architecture-shared-technical.md#L71-L73) fixes target identity, multi-parent closure, immediate use/reminder cancellation, serialized egress and late-result suppression while preserving unrelated roots. Export artifacts follow the same lifecycle. The inherited [D5 owner-control warning](../../product-policies.md#L63) remains required; a duplicate deletion-preview UI specification in the spine is unnecessary to settle the cross-module contract.                                                                                                                                          |
| Security **SEC-03** — removed learner's export              | **Resolved** | [AD-3](../architecture-shared-technical.md#L64-L65) explicitly exempts the narrow authenticated self-history action from active enrollment, not from subject/action authorization. It excludes bank data, other learners and new activity. Downloads stay behind that authorization boundary; [AD-4](../architecture-shared-technical.md#L71-L72) applies the same authorization/deletion path and 24-hour expiry to export artifacts. Ordinary course-content/reporting permissions are not reopened.                                                                                                              |
| Security **SEC-04** — DNS check/use race                    | **Resolved** | [AD-11](../architecture-shared-technical.md#L121) requires the **actual connected address** to be a vetted public address, revalidates redirects, and explicitly forbids DNS rebinding or a fresh unvalidated connection from bypassing the check. A preflight-only lookup followed by an independently resolving fetch is therefore noncompliant. Adapter/package and connection-level attack proof remain G3 work.                                                                                                                                                                                                |
| Security **SEC-05** — passive media egress                  | **Resolved** | [AD-12](../architecture-shared-technical.md#L127-L129) requires registered scoped learning assets, controlled acquisition, same-origin authenticated `no-store` delivery, CSP denial of unapproved remote loads, and no shared/unauthenticated optimizer workaround. Arbitrary passive image/font/audio/embed requests are forbidden; citations are explicit navigation, not preloads. These resource rules are not conditional on publication or instructor approval, so draft preview/personal renderers cannot bypass them.                                                                                      |
