- (event) Verified TCP explanation against first-party RFC 9293, retrieved 2026-10-19: section 3.4.1 requires exchange and acknowledgment of both peers' initial sequence numbers and combines the server acknowledgment and SYN into one message; section 3.5 identifies avoiding confusion from old duplicate initiations as the principal reason. In the basic handshake the third ACK acknowledges the server SYN; after two messages the server has not received that confirmation. This is not perfect common knowledge or cryptographic authentication, and a human greeting is not an equivalent protocol requirement. Source: https://www.rfc-editor.org/rfc/rfc9293.html#section-3.4.1 and https://www.rfc-editor.org/rfc/rfc9293.html#section-3.5 .
