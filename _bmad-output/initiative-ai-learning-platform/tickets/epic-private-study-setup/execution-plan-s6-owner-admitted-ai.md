## What S6 must deliver (from delivery-checks S6, reworded to the owner decision)

1. A versioned processor configuration row that is `eligible` and dispatchable through the EXISTING consent/admission/settle machinery (no bypass of `admitDispatch`/`settleDispatch`).
2. An AI draft pipeline: learner action → admission → queued job → bounded prompt from acknowledged/selected source revisions + goal/topic → one OpenAI-compatible chat completion → strict JSON validation → candidate topics + draft plan (planSchema-shaped) → advisory result the learner edits/confirms through the EXISTING savePlan/confirmPlan flow. AI never auto-confirms; drafts are UI suggestions, not plan revisions.
3. Honest states: pending (bounded by 120s), failed (invalid-output/timeout/rate-limit/authentication/transport/budget/quota), blocked (consent/withdrawn/fence), all content-free in logs; retry creates a new command; no duplicate accepted effect (settle is idempotent, existing).
4. Budget accounting: `app.ai_dispatch_ledger` records per-dispatch usage tokens (untrusted provider claims, labeled as such); dispatch blocked when ledger total + requested max exceeds the cap.
5. Lifecycle: ai_draft_request rows are root-scoped derivatives — purged on root deletion, denied after fences, exported as diagnostic-adjacent metadata (no excerpts in export; the draft result itself is owner content and MAY be exported under a new category only if trivially wired — otherwise register as skipped with reason; choose the simpler honest option).
6. Live smoke evidence: `scripts/ai-smoke.ts` (manual, not part of `npm run checks`) makes ONE real call via the production path, writes `.local/ai-smoke-<date>.json` (ok/model/usage/chars — never the key, never full prompt text beyond what the fixture already is), prints a content-free summary.
